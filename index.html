How the agent reads 92,000 words without chunking them

The filing stays whole. The agent gets three read-only tools and decides which to use next. These run on the real filing, in your browser.

01 Keyword search

Every line where a word or number appears, with its line number. Commas and table borders are ignored, so "1900" finds "1,900".

02 Table of contents

Every heading with its line number, so the agent jumps to the right section instead of guessing.

03 Read lines

Up to 400 lines at once, so the agent can widen its read until it sees the heading that explains a number.

The fine print

How the test worked

The document

Anthropic's S-1 amendment filed with the SEC on 17 November 2026, converted to text: 4,733 lines and about 92,000 words. Read the filing.

RAG and keyword search

Both split the filing into 504 chunks of about 2,000 characters. RAG ranks them with the bge-base embedding model, keyword search with BM25. A question counts when the answer is inside the top 8 chunks. At 16 chunks RAG finds 8 and keyword search 7.

The agent

Claude Sonnet in Claude Code with every tool removed except the paper's search, outline and line reader. Each question ran on its own, and the replays show its real tool calls at their recorded pace.

Your own questions

RAG and keyword search run live on your device. The agent runs on Qwen3, an open model from Hugging Face, inside your browser with the same three tools. It needs a recent desktop browser with WebGPU and a one-time download of about 1 to 2.3 GB. It is much smaller than Claude, so expect slower and less reliable answers.

Limits

Ten questions on one document, so this is a demo, not a benchmark. RAG and keyword search are scored on whether the answer reached the model, the agent on its final answer. The agent is slower and costs more: about 9 seconds and 8 cents a question.
